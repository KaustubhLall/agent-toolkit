# Applying ECC on this host

ECC source: `934195f955cf0da847d59fcd6f68856bce112d8b`, MIT Affaan Mustafa.
`SOURCE.json` records unchanged vendored file hashes. Adapted files live outside
`library/` and `vendor/`; their installed hashes are in the migration receipt.

## Native operating model

- Use `orchestrator` to select explore, debug, contract-first or delivery mode;
  incorporate ECC repo scans, plan chains, specialist reviews and evidence gates.
- Use host collaboration for worker lifecycle, native worktrees for isolation,
  app automations for user-requested recurring work and native usage tools for
  account limits. Match a role to the task and model to demonstrated difficulty.
- Use operations for execution bookkeeping when dependencies, ownership or
  multi-session recovery justify persistent state. Link tracker/task IDs rather
  than making the local ledger authoritative for external issue status.
- Lifecycle hooks are small native adapters: their exact implementation and
  trust state determine behavior. Reading the upstream corpus starts no service.
- Use reviewed lessons in existing task/project docs; don't automatically turn
  transcript fragments into global policy. The user's explicit memory controls
  remain authoritative. Evaluate repeated lessons before promoting them.

## Translation and corrections

| ECC construct | Effective adaptation |
|---|---|
| Claude Task/Agent, fixed Opus/Sonnet/Haiku, Devin or tmux worker | Native collaboration; abstract roles, Luna for bounded work where appropriate, parent-selected supported models. |
| Slash commands and `/orchestrate` recipes | Read the recipe, execute its useful steps with available tools. No fabricated command availability. |
| Mandatory TDD, fixed review counts, 80% coverage, numeric harness grade | Choose meaningful tests/gates for the behavior and failure cost. File-count scores are not capability evidence. |
| Automatic commit/push/deploy/send in a recipe | Use current user authorization; local method text does not grant an external action. |
| Bash/tmux daemons, cron loops | Native host lifecycle and automation; WSL/tmux only for tasks actually using that stack. |
| Browser/MCP presets with `npx ...@latest` | Existing installed browser and app capabilities first; add a missing service when a real task needs it, after version/source review. |
| Continuous-learning observations/instincts | Evidence-linked scoped lessons and explicit promotion to the existing owner docs. No competing opaque global store. |
| PostgreSQL nullable ADD COLUMN described as 'no lock' | May require ACCESS EXCLUSIVE; inspect server version, table size and runner transaction. `DO ... COMMIT` has transaction-context restrictions. |
| MLE promotion comparisons | Reject missing, non-finite/NaN and incomparable metrics before threshold comparisons. |
| Cost pipeline checks only accumulated spend | Reserve/check projected next-call cost plus retries before dispatch; a usage reset is never inferred. |
| Cache keyed only on input bytes | Include processor/config/schema/dependency identity that affects the output. |

The complete corpus is available on demand, including niche domains and external
integrations. A catalog `defer` disposition records an earlier assessment, not a
permanent ban. Verify availability and applicability when the task needs it.
Upstream install/repair/update scripts are retained for inspection; do not call
them to operate this curated installation. Update the pinned source and regenerate
the reviewed package through its installation runbook.
