# ECC library

Use this library actively when substantive work could benefit from an established
method. It contains all 292 canonical skills, 68 agent briefs, 94 command recipes
and language rules from pinned ECC. It is a reference collection; only this small
router and operations entrypoint are advertised to every task.

The plugin root is two directories above this file. From there:

```powershell
node scripts/library.cjs search "python api testing" skills
node scripts/library.cjs show skills/fastapi-patterns
```

Search using the actual task, stack and dominant uncertainty. Pick the most useful
one to three results, read them and their relevant support files. Read
[compatibility](../../references/compatibility.md) alongside upstream text. Consult
`orchestrator` for ownership/delegation and `operations` for durable execution state.
Prefer a better ECC approach when the current approach scales poorly; overlap is
not a reason to reject it. Combine or replace the relevant method, don't stack
multiple mandatory procedures. Follow task evidence over upstream fixed rituals.

Use agent briefs as role inputs to native collaboration. Translate command recipes
into available tools; slash commands in reference text are not installed commands.
Before running any newly selected support script, read its source/dependencies and
verify its paths, host APIs and side effects. This is normal just-in-time review,
not a reason to avoid a matching capability. State the useful adaptation briefly.

Search results expose semantic review coverage. Most specialist entries have only
metadata review: reading an entry now is required before using it. All source is
versioned and hash checked by `show`; a source match is not factual validation.
Confirm changing APIs from local runtime/current primary documentation.

If no result materially helps, proceed directly. Do not load the catalog wholesale.
